# Основной поисковый этап: три среды

**Назначение:** основной протокол и воспроизведение. **Статус на 25 октября 2026 года:**
поисковый этап завершён, все 1 620 позиций выполнены и проверены. Подтверждающая
фаза ещё не выполнена. Разбор — [RESULTS.md](RESULTS.md), определения метрик и файлов —
[METHODOLOGY.md](METHODOLOGY.md). Числа состояния ниже относятся к авторскому набору
данных; результаты обучения не входят в клон репозитория.

Состав исследования утверждён по пилотам: CartPole-v1, Acrobot-v1 и Pendulum-v1.
Сравнение проводится внутри среды при фиксированном бюджете; достижение полной
сходимости всех настроек не предполагается. На 204 800 шагах PPO в Pendulum ещё
улучшался, поэтому этот бюджет не называется доказанным временем сходимости.

## Условия

| Среда | Бюджет | Частота оценки | Порог |
|---|---:|---:|---|
| CartPole-v1 | 51 200 | 2 560 | 475 |
| Acrobot-v1 | 102 400 | 5 120 | -100 |
| Pendulum-v1 | 204 800 | 5 120 | Не используется |

На конфигурацию — пять поисковых seed 0–4. Оценка: 10 sampled и 10 deterministic
эпизодов на контрольную точку, 30 + 30 независимых финальных эпизодов. Сохраняются
предыдущие архитектура, оптимизаторы baseline, обработка действий и изоляция RNG.

Идентификатор Pendulum `pendulum-pilot-v1` сохранён для совместимости формата и
настроек среды. Роль эксперимента задаёт отдельное поле phase: здесь search.
Пилотные команды по-прежнему используют 102 400 шагов. У frozen config всегда
сохраняется явно записанный бюджет, независимо от последующих изменений пресетов.

## Общее ядро и объём

Серии: baseline, learning_rate, n_steps, gae_lambda, ent_coef, grid_lr_steps,
grid_lr_entropy. Две сетки — learning_rate × n_steps и learning_rate × ent_coef.
Точные определения сохранены в самом файле плана:

| Фактор | A2C | PPO |
|---|---|---|
| learning_rate, обычная серия | 0.00001, 0.0001, 0.0003, 0.0007, 0.001, 0.003, 0.01 | Те же значения |
| n_steps | 5, 16, 64, 256 | 64, 256, 1024, 2048 |
| gae_lambda | 0.8, 0.9, 0.95, 0.99, 1 | Те же значения |
| ent_coef, обычная серия | 0, 0.001, 0.01, 0.05, 0.1 | Те же значения |
| learning_rate, обе сетки | 0.0001, 0.0003, 0.0007, 0.003 | Те же значения |
| ent_coef, сетка | 0, 0.001, 0.01, 0.05 | Те же значения |

В сетке с n_steps используются все четыре уровня соответствующего алгоритма.
Обе сетки имеют размер 4 × 4. Baseline не подбирается: это явно заданные настройки
из [методики](METHODOLOGY.md#baseline-и-общие-условия).

| Пара среда–алгоритм | Позиции конфигураций | Запуски |
|---|---:|---:|
| Каждая из шести пар | 54 | 270 |
| Все три среды и оба алгоритма | 324 | 1 620 |

Это 1 080 различных условий с учётом seed. Повторы стандартных настроек в разных
сериях не считаются дополнительными независимыми наблюдениями. Между разными путями
серий отдельного кэша одинаковых моделей нет; завершённые запуски по тому же пути
проверяются и переиспользуются.

Диапазоны n_steps у A2C/PPO различаются. Чувствительность по этому параметру нельзя
непосредственно ранжировать как эффект на одном и том же диапазоне. Общие настройки
алгоритмов описываются явно; сравниваются реализации с заявленными native baseline,
а не только различия математических функций потерь.

## Фиксированный план

`configs/main_search_v1.json` содержит базовые конфигурации сред, версии, идентификатор
обучения, seed, точные серии и их дизайны, baseline алгоритмов и контрольную сумму.
При несовпадении версий, кода обучения или зарегистрированных серий выполнение
останавливается до обучения. Явно проверенные исторические версии допускаются через
аудит compatibility.json. План не перезаписывается другим содержимым: для изменений
используйте новый файл и сохраняйте предыдущий в истории Git.

Проверяются точные версии, включая Python 3.10.22. Одной записи «Python 3.10»
недостаточно для совпадения с фиксированным окружением. Редактировать versions в
готовом плане ради обхода проверки нельзя: иное окружение требует отдельного
обоснования совместимости или нового плана, а не незаметного смешения результатов.

Файл компактен: полная матрица разворачивается из сохранённых определений, а не из
текущих значений списка серий. Соответствие определениям, которые записывает trainer,
проверяется перед запуском.

```powershell
Set-Location C:\XD\Projects\A2C_RL
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --list
```

Предпросмотр не создаёт результаты и не запускает обучение. Он проверяет существующие
файлы и показывает completed/pending/blocked. На дату завершения поиска:
**completed=1620, pending=0, blocked=0**, отсутствующих ячеек сеток нет.
В чистом клоне без исходных результатов будет pending=1620. Фактическое состояние
своего каталога всегда проверяйте через --list; опубликованные сводки не заменяют
проверку исходных файлов обучения.

## Выполнение частями

По умолчанию используется `results_search`: старые данные CartPole остаются на месте,
новые среды получают вложенные каталоги. Указать другой --out можно, но там прежних
готовых результатов не будет. Не добавляйте --force ради переиспользования.

```powershell
# Воспроизвести общее ядро PPO на CartPole
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --envs CartPole-v1 --algos ppo --workers 8

# Основные серии Acrobot: оба алгоритма
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --envs Acrobot-v1 --workers 8

# Основные серии Pendulum: оба алгоритма, уже с бюджетом 204 800
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --envs Pendulum-v1 --workers 8
```

Воспроизвести весь план или выполнить недостающую часть можно одной командой:

```powershell
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --workers 8
```

Совместимые готовые запуски не изменяются. Незавершённые при совместимых конфигурациях
начинаются заново. Активный lock, несовпадающие условия и повреждённые артефакты дают
blocked до запуска серии. Оставшийся после аварии lock удаляется только после
проверки отсутствия работающего процесса. Ошибки запусков сохраняются, команда
завершается с ненулевым кодом, а повтор использует уже выполненную часть.

Доступны фильтры --envs, --algos, --groups и --seeds. Они выбирают подмножество файла,
не добавляют новые условия. Например --groups baseline --seeds 0. Для изменения
диапазонов создаётся новый план, а не редактируется действующий во время исследования.

## Анализ

```powershell
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search --study-plan configs/main_search_v1.json --out analysis_main_search
```

В основном отчёте учитывается только матрица файла плана. Дополнительные серии CartPole
остаются в данных и получают outside_study в аудите. manifest study в analysis.json
показывает expected_runs, loaded_runs и missing_or_invalid_runs: выводы по полному
плану нельзя делать, пока есть необъяснённые пропуски.
Совпадение настроек без совпадения версий библиотек и проверенного кода обучения
не засчитывается в покрытие: такие результаты исключаются и учитываются отдельно
в incompatible_study_runs. Дополнительные серии учитываются в outside_study_runs.

Обычный анализ всех сохранённых поисковых серий остаётся доступным:

```powershell
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search --out analysis_search
```

Основные показатели: исходная итоговая sampled-награда, AUC, межзапусковый разброс,
просадки; при определённом пороге также достижение и сохранение качества. Числа и
интервалы сравниваются внутри среды. Исходные награды или нормированные AUC трёх
задач не усредняются в общий рейтинг. Пять поисковых seed не заменяют независимую
подтверждающую фазу. Её выбранные настройки и диапазоны фиксируются отдельно после
анализа, до запуска новых seed.

## Прежние команды

Все команды sweep и старые серии сохранены. Без --env выбирается CartPole.
Для search/confirmatory Pendulum теперь по умолчанию 204 800 шагов; для pilot —
прежние 102 400. Сохранённый --config не меняется автоматически.

Полный каталог дополнительных серий CartPole находится в [EXPERIMENTS.md](EXPERIMENTS.md).
Он шире общего ядра и не означает, что все дополнительные серии PPO выполнены.

Подготовить другой фиксированный план без обучения:

```powershell
.venv/Scripts/python.exe -m a2c_research.study --prepare configs/another_study.json --envs Acrobot-v1 --algos a2c --suite core --seeds 0 1 2 3 4
```

Одиночное обучение по сохранённой конфигурации, в отдельном каталоге:

```powershell
.venv/Scripts/python.exe -m a2c_research.train --config configs/baseline.json --out results_manual
.venv/Scripts/python.exe -m a2c_research.train --env Acrobot-v1 --algo a2c --seed 1 --out results_manual_acrobot
```

Изменение параметров вручную доступно через --set, параметров политики — через
--policy-set. Такие запуски не дополняют фиксированный основной план автоматически.
Числа после --seeds — конкретные номера: --seeds 10 означает один seed, не десять.

## Подтверждающая фаза: механизм есть, план ещё не утверждён

Выбор настроек, диапазонов и основных показателей фиксируется по поисковым данным
до просмотра новых обучающих seed. Проверка только победителя поиска не подтверждает
чувствительность по диапазону или взаимодействие: для этого заранее сохраняют
нужные уровни фактора или ячейки сетки. Перебирать настройки по подтверждающим seed нельзя.

Механизм sweep --config читает полный config.json выбранного запуска либо отдельный
JSON конфигурации и меняет только phase/seed. После создания и согласования
configs/selected_a2c.json синтаксис будет следующим; **этого файла и утверждённого
подтверждающего плана в репозитории пока нет**:

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --config configs/selected_a2c.json --phase confirmatory --out results_confirmatory --list
.venv/Scripts/python.exe -m a2c_research.sweep --config configs/selected_a2c.json --phase confirmatory --out results_confirmatory --workers 8
```

По умолчанию confirmatory использует 20 seed 1000–1019. Другой набор задаётся явно
после согласования. Seed ниже 1000 запрещены для confirmatory, seed от 1000 —
для search/pilot. Число 20 — рабочая отправная точка, не гарантия статистической мощности.
Команды приведены для описания возможностей и не являются решением о составе следующей фазы.
