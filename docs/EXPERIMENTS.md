# Расширенный план исследования

Объект исследования: стабильность обучения и чувствительность A2C/PPO на CartPole-v1.
Все приведённые ниже серии объявлены в коде. Наличие серии не означает, что её
эксперименты уже выполнены. Просмотреть план можно без обучения:

```powershell
Set-Location C:\XD\Projects\A2C_RL
.venv/Scripts/python.exe -m a2c_research.sweep --suite all --list --summary
.venv/Scripts/python.exe -m a2c_research.sweep --algo ppo --suite all --list --summary
```

## Обычные серии A2C

| Серия | Значения | Позиции |
|---|---|---:|
| baseline | Стандартные параметры A2C | 1 |
| learning_rate | 0.00001, 0.0001, 0.0003, 0.0007, 0.001, 0.003, 0.01 | 7 |
| n_steps | 5, 16, 64, 256 | 4 |
| gamma | 0.9, 0.95, 0.99, 0.999 | 4 |
| gae_lambda | 0.8, 0.9, 0.95, 0.99, 1 | 5 |
| ent_coef | 0, 0.001, 0.01, 0.05, 0.1 | 5 |
| vf_coef | 0.1, 0.25, 0.5, 1, 2 | 5 |
| max_grad_norm | 0.1, 0.5, 1, 5 | 4 |
| n_envs | 1, 2, 4, 8 при n_steps = 64 / n_envs | 4 |
| net_arch | [16,16], [64,64], [256,256] в каждой ветви | 3 |
| activation | Tanh, ReLU | 2 |
| normalize_advantage | False, True | 2 |
| use_rms_prop | RMSprop, Adam | 2 |
| **Всего** | **13 серий** | **48** |

В серии `n_envs` контроль — одна среда с n_steps=64, а не обычный baseline с
n_steps=5. Изменение длины траектории при фиксированном размере rollout является
частью дизайна этой серии; полностью отделить эти два эффекта здесь нельзя.
Фиксированный размер rollout сохраняет число обновлений за бюджет.

## Двумерные сетки

| Серия | Первая ось | Вторая ось | Позиции |
|---|---|---|---:|
| grid_lr_steps | learning_rate: 0.0001, 0.0003, 0.0007, 0.003 | n_steps: 5, 16, 64, 256 | 16 |
| grid_gamma_lambda | gamma: 0.95, 0.99, 0.999 | gae_lambda: 0.9, 0.95, 1 | 9 |
| grid_lr_entropy | learning_rate: 0.0001, 0.0003, 0.0007, 0.003 | ent_coef: 0, 0.001, 0.01, 0.05 | 16 |
| **Всего** | | | **41** |

Итого A2C: **89 позиций × 5 seed = 445 запусков**. Часть позиций совпадает по
условиям обучения, но служит контролем в разных сериях. Всего различных условий
с учётом seed — **290**. Повторы контролей не увеличивают независимую выборку.
Автоматическое переиспользование завершённых запусков работает внутри их пути;
между разными сериями отдельного кэша моделей нет.

Для PPO объявлены общие серии, n_steps: 64, 256, 1024, 2048; n_envs при rollout=2048;
дополнительно clip_range, n_epochs, batch_size. Доступны пять сеток: три аналогичные
A2C (с PPO-диапазоном n_steps), learning_rate × clip_range и learning_rate × n_epochs,
как у коллеги. Полный вспомогательный план PPO — **20 серий, 135 позиций, 675 запусков**
при пяти seed. Выполнять его целиком необязательно: повторять следует нужные для
сравнения серии с общими условиями. У A2C отсутствуют batch_size, n_epochs и clip_range.

## Порядок выполнения

1. Сохранить пилот и предварительные выводы. Его seed 0–2 уже просмотрены и не
   являются независимым подтверждением гипотез, выбранных после просмотра пилота.
2. Выполнить основные обычные серии на поисковых seed 0–4, затем дополнительные.
3. Выполнить сетки. Временные оценки получать по фактическим первым запускам;
   число процессов выбрать по доступной памяти и загрузке CPU.
4. Зафиксировать настройки и проверяемые диапазоны до подтверждающей фазы.
5. Проверить их на новых seed, например 1000–1019. Подтверждать чувствительность
   нужно на нескольких уровнях фактора; проверка только лучшей настройки не подтверждает диапазон.

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --suite primary --workers 2 --out results_search
.venv/Scripts/python.exe -m a2c_research.sweep --suite ofat --workers 2 --out results_search
.venv/Scripts/python.exe -m a2c_research.sweep --suite grids --workers 2 --out results_search
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search --out analysis_search
```

Повторный `--suite ofat` переиспользует уже завершённые основные серии при неизменных
условиях и коде обучения. `--suite all` объединяет обычные серии и сетки.
`--groups` позволяет запускать отдельные серии; его нельзя сочетать с `--suite`.

Общие сетки PPO можно повторить отдельно:

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --algo ppo --groups grid_gamma_lambda grid_lr_entropy --workers 2 --out results_search
```

## Что проверять в анализе

- `audit.csv`: пропуски, незавершённые/повреждённые запуски, конфликтующие копии.
- `summary.csv`: AUC, итоговая награда, просадки, доля достижения и сохранения качества.
- `sensitivity.csv`: диапазон средней AUC только при полных уровнях и одинаковых seed.
- `sensitivity_comparison.csv`: явная проверка совпадения диапазонов A2C/PPO и
  связанных контролей. Несопоставимые столбцы на общем графике отмечены звёздочкой.
- `grid_cells.csv`: все заявленные ячейки, включая отсутствующие; число seed на ячейку.
- `interactions.csv`: разности разностей по одинаковым seed четырёх ячеек. Отсутствующие
  ячейки и несогласованные seed дают статус incomplete, а не численный вывод.
- `comparison.csv`: разности A2C–PPO по сопоставимым условиям и конфигурациям.
- `analysis.json`: условия группировки, источник анализа и список дополнительных рисунков.

Графики: кривые средних и интервалы; траектории каждого seed с подписями; распределения
метрик; диагностические entropy_loss/value_loss/explained_variance, а для PPO также
approx_kl/clip_fraction; тепловые карты шести показателей; взаимодействия в обоих
направлениях; сравнения A2C/PPO; общие обзоры обычных параметров и чувствительности.
PNG и PDF — два формата одного рисунка, а не разные экспериментальные результаты.

Чувствительность нельзя ранжировать между алгоритмами по разным диапазонам/сеткам
или разным контрольным rollout. Для n_steps диапазоны различаются, для n_envs
различаются контрольные размеры rollout. Одинаковое название серии не устраняет
эти различия. Тепловые карты, линии и нескорректированные интервалы — инструменты
исследования, а не автоматическое доказательство взаимодействия или превосходства.
