# A2C и PPO: стабильность обучения и чувствительность к гиперпараметрам

Экспериментальный проект для статьи **«Сравнительный анализ стабильности обучения
и чувствительности к гиперпараметрам A2C и PPO в одноагентной среде»**.
Исследуются три стандартные одноагентные задачи Gymnasium. Ядра A2C и PPO взяты
из Stable-Baselines3; проект задаёт протокол обучения, серии экспериментов,
независимую итоговую оценку, проверку результатов и статистический анализ.

## Материалы проекта

Ветка **a2c** репозитория [RATARETO/A2CvsPPO](https://github.com/RATARETO/A2CvsPPO/tree/a2c)
содержит самостоятельную версию проекта вместе с полными результатами основного
поискового исследования. История разработки перенесена из
[akogarechau/A2C_RL, коммит 913e4cb](https://github.com/akogarechau/A2C_RL/tree/913e4cb4e7f4e59208329fbdcb8186598e976bac).

## Текущий этап

По состоянию на **25 октября 2026 года основной поисковый этап завершён**:

- CartPole-v1, Acrobot-v1 и Pendulum-v1; A2C и PPO в каждой среде.
- По пять обучающих seed: 0–4.
- Выполнены все **1 620 позиций запусков**, без пропусков и несовместимых результатов.
- Получены таблицы, кривые обучения, траектории seed, тепловые карты и контрасты взаимодействий.
- **Подтверждающая фаза ещё не выполнена**; её настройки и гипотезы предстоит зафиксировать.

Фиксированный план — [configs/main_search_v1.json](configs/main_search_v1.json).
В нём 324 позиции конфигураций. С учётом повторяющихся контролей это
**1 080 различных условий обучения с seed**, а не 1 620 независимых наблюдений.
Числа описывают выполненное исследование. В этой ветке результаты обучения включены
в клон репозитория вместе с кодом.

## Условия основного исследования

| Среда | Действия | Бюджет переходов | Частота оценки | Порог средней награды |
|---|---|---:|---:|---:|
| CartPole-v1 | Дискретные | 51 200 | 2 560 | 475 |
| Acrobot-v1 | Дискретные | 102 400 | 5 120 | −100 |
| Pendulum-v1 | Непрерывные | 204 800 | 5 120 | Не задан |

Общие условия: `MlpPolicy`, отдельные ветви actor/critic `[64, 64]`, Tanh,
одна обучающая среда, CPU и один поток PyTorch на обучение. Нормализация наблюдений
и наград не используется. На контрольную точку — 10 sampled и 10 deterministic
эпизодов; после обучения — отдельные 30 + 30 эпизодов на другом наборе оценочных seed.
Основные метрики используют sampled-политику.

В общее ядро входят baseline, однофакторные серии `learning_rate`, `n_steps`,
`gae_lambda`, `ent_coef` и две сетки: `learning_rate × n_steps`,
`learning_rate × ent_coef`. В каждой паре среда–алгоритм — 54 позиции × 5 seed = 270 запусков.
Baseline — явно заданные стандартные настройки конкретного алгоритма; он не выбирается
как лучший результат поиска. Дополнительные серии CartPole сохранены отдельно.

## Полученные результаты

Независимая итоговая sampled-награда: **среднее ± выборочное стандартное отклонение
между пятью обучениями**. Для отрицательной награды значение ближе к нулю лучше.

| Среда | A2C baseline | PPO baseline |
|---|---:|---:|
| CartPole-v1 | 235,4 ± 158,5 | 497,9 ± 4,8 |
| Acrobot-v1 | −247,7 ± 161,0 | −84,8 ± 2,0 |
| Pendulum-v1 | −850,0 ± 233,7 | −356,2 ± 120,2 |

На стандартных настройках PPO показывает более высокую итоговую награду, меньший
межзапусковый разброс и меньшие средние максимальные просадки во всех трёх средах.
Чувствительность зависит от параметра и среды: например, размах AUC по learning rate
у PPO выше в CartPole и Pendulum. Сетки показывают зависимость эффекта одного
параметра от другого. Небольшие просадки могут сочетаться с низким качеством.

Это **поисковые результаты при фиксированных бюджетах**. Они не устанавливают
полную сходимость или общее превосходство алгоритма. Разбор, интервалы,
кандидаты настроек и ключевые рисунки находятся в [docs/RESULTS.md](docs/RESULTS.md).

## Установка

Python **3.10.22**, Stable-Baselines3 **2.9.0**, Gymnasium **1.4.0**, PyTorch **2.10.0**,
NumPy **2.2.6**, pandas **2.3.3**, Matplotlib **3.10.8**.
Прямые зависимости заданы в `pyproject.toml`, точные версии окружения —
в `requirements-frozen.txt`. Все команды PowerShell выполняются из корня клонированного проекта:

```powershell
Get-Location
py -3.10 -m venv .venv
.venv/Scripts/python.exe --version
.venv/Scripts/python.exe -m pip install -r requirements-frozen.txt
.venv/Scripts/python.exe -m pip install --no-deps --no-build-isolation -e '.[dev]'
.venv/Scripts/python.exe -m pip check
```

Существующее окружение повторно создавать не требуется. Глобальные пакеты не нужны.
Селектор py -3.10 выбирает установленный интерпретатор ветки 3.10: для фиксированного
плана требуется именно 3.10.22, что нужно проверить до установки зависимостей.
На Linux/macOS используйте `python3.10 -m venv .venv` и `.venv/bin/python`
вместо Windows-пути. Точное соответствие версий проверяется перед выполнением плана.

## Запуск и анализ

Посмотреть план и проверить имеющиеся локальные результаты без обучения:

```powershell
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --list
```

Воспроизвести исследование или выполнить недостающую часть:

```powershell
.venv/Scripts/python.exe -m a2c_research.study --plan configs/main_search_v1.json --workers 8
```

Совместимые завершённые запуски проверяются и переиспользуются. `--workers` — число
независимых обучений в процессах, не число сред внутри модели. Значение 8 использовалось
на рабочей машине; на другой машине выбирайте по доступным CPU и памяти.
Для выполнения частями доступны `--envs`, `--algos`, `--groups`, `--seeds`;
примеры и обработка незавершённых запусков — в [основном протоколе](docs/MAIN_STUDY.md).

Повторить полный анализ в отдельном каталоге, сохранив опубликованный отчёт:

```powershell
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search --study-plan configs/main_search_v1.json --out analysis_reproduced
```

Для короткой проверки работоспособности, не для результатов статьи:

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --quick --workers 1
.venv/Scripts/python.exe -m a2c_research.analyze --results results_quick --out analysis_quick
```

## Доступность данных и воспроизводимость

В этой ветке Git содержит код, тесты, фиксированный план, документацию,
численный снимок `docs/data/main_search_v1/`, а также **полные каталоги
results_search и analysis_main_search**. В исходных результатах сохранены 1 620
позиций основного плана и 175 дополнительных поисковых запусков CartPole;
дополнительные данные отделяются фильтром --study-plan.

Для повторного анализа повторное обучение не требуется. Сохранённые конфигурации,
модели, промежуточные и финальные оценки проверяются анализатором по контрольным
суммам. .gitattributes сохраняет байты результатов без изменения окончаний строк.
Краткий снимок в docs остаётся производным набором и не заменяет исходные файлы.
Другие пилотные и проверочные каталоги, окружение, временные файлы и .refs не включены.

Референс `.refs/RL_and_PPO` использовался для анализа проекта коллеги.
PPO основного исследования выполнен здесь по тому же протоколу, что и A2C.
Старые результаты коллеги не подменяют эти запуски и не включаются в строгие
сравнения автоматически. Подробнее — [методика](docs/METHODOLOGY.md#сопоставимость-и-референс).

## Следующий этап

До новых запусков предстоит согласовать основные показатели, правила выбора
настроек и проверяемые эффекты. Затем — зафиксировать небольшой подтверждающий
план и проверить его на независимых seed, например 1000–1019. Проверка одного
лучшего варианта не подтверждает чувствительность по диапазону или взаимодействие
факторов. Пока отдельный подтверждающий план не утверждён и не выполнен.
