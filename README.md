# A2C: стабильность обучения и чувствительность к гиперпараметрам

Самостоятельный экспериментальный проект для статьи **«Сравнительный анализ
стабильности обучения и чувствительности к гиперпараметрам A2C и PPO в одноагентной
среде»**. Алгоритмы взяты из Stable-Baselines3; собственной реализации ядра A2C здесь
нет. Основной алгоритм — A2C, PPO доступен для контрольных повторений по тому же
протоколу. Каталог `.refs/` используется только как источник для чтения.

Проект не запускает основное исследование автоматически. Проверочные короткие
запуски проверяют работоспособность и не являются результатами для статьи.

Расширение для Acrobot-v1 и Pendulum-v1, протокол и команды пилота описаны в
[docs/MULTI_ENV_PROTOCOL.md](docs/MULTI_ENV_PROTOCOL.md). Прежние команды CartPole,
серии и результаты сохранены. Без `--env` по-прежнему выбирается CartPole-v1.

Основной этап на трёх средах зафиксирован в `configs/main_search_v1.json`.
Порядок запуска, объём и анализ общего ядра: [docs/MAIN_STUDY.md](docs/MAIN_STUDY.md).
Поисковые и подтверждающие запуски Pendulum теперь используют 204 800 шагов;
пилот сохраняет 102 400. Предпросмотр: `python -m a2c_research.study --plan configs/main_search_v1.json --list`
через интерпретатор `.venv`.

## Протокол `cartpole-stability-v1`

| Условие | Значение |
|---|---|
| Среда | `CartPole-v1`, стандартный предел 500 шагов |
| Политика | `MlpPolicy`, отдельные ветви actor/critic `[64, 64]`, Tanh |
| Обучающие среды | 1; стандартная векторная оболочка SB3 |
| Бюджет | 51 200 обучающих переходов |
| Оценка | На шаге 0, затем каждые 2 560 переходов, включая конец |
| Промежуточная оценка | 10 эпизодов для sampled и 10 для greedy |
| Независимая итоговая оценка | 30 эпизодов для каждой политики |
| Основная политика для метрик | Sampled, действия из распределения политики |
| Порог | Средняя награда >= 475 на двух последовательных оценках |
| Нормализация наблюдений/наград | Не используется |

51 200 вместо 50 000 выбраны для целого числа стандартных rollout PPO (2048)
и A2C (5). Все объявленные значения `n_steps` также делят бюджет. Произвольный
конфиг с превышением бюджета отклоняется до обучения. Число переходов — суммарное
по средам, а не число вызовов векторной `step()`.

Все параметры алгоритмов заданы явно в `config.py`. Базовый A2C использует
RMSprop, learning rate 0.0007, `n_steps=5`, `gamma=0.99`, `gae_lambda=1`,
`ent_coef=0`, без нормализации преимущества. Базовый PPO использует Adam,
learning rate 0.0003, `n_steps=2048`, `batch_size=64`, `n_epochs=10`,
`gae_lambda=0.95`, `clip_range=0.2`, с нормализацией преимущества. Это сравнение
заявленных реализаций с их стандартными настройками; оно не изолирует только
математическую функцию потерь.

Оценочные эпизоды имеют явные seed: `1_000_000 + i` во время обучения и
`2_000_000 + i` после обучения. Все модели оцениваются на одинаковых начальных
состояниях. На каждой контрольной точке используются те же эпизоды. Sampled и
greedy также видят одинаковые начальные состояния. Генераторы Python, NumPy
и CPU PyTorch после оценки восстанавливаются; режим policy тоже восстанавливается.
Оценка не потребляет случайность обучения. Эпизоды оценки не входят в бюджет обучения.

Промежуточная оценка на шаге t относится к доступной в этот момент политике:
некоторые из уже собранных переходов ещё могут находиться в rollout до обновления.
Последняя контрольная точка выполняется **после последнего обновления**. Дополнительно
сохраняется `_n_updates` SB3; его семантика различается у A2C/PPO и не используется
как общий критерий эффективности.

`train_time_sec` включает промежуточные оценки и запись их файлов, как у коллеги;
время оценки записано отдельно. Время не является исследуемым результатом этой статьи.

## Порядок экспериментов

### 1. Проверка и пилот

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --quick
.venv/Scripts/python.exe -m a2c_research.analyze --results results_quick --out analysis_quick
.venv/Scripts/python.exe -m a2c_research.sweep --phase pilot --groups baseline --seeds 0 1 2 --out results_pilot
```

`--quick` запускает одну модель на 10 240 шагах с уменьшенным числом оценочных
эпизодов. Её условия образуют отдельную группу анализа. Пилот по полной схеме
нужен для оценки длительности запусков и достаточности бюджета. Пилотные результаты
не следует объявлять независимым подтверждением выбранных по ним настроек.

### 2. План и исследование чувствительности

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --list
.venv/Scripts/python.exe -m a2c_research.sweep --groups baseline learning_rate --list
.venv/Scripts/python.exe -m a2c_research.sweep --groups baseline learning_rate --workers 2
.venv/Scripts/python.exe -m a2c_research.sweep --groups n_steps gae_lambda ent_coef --workers 2
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search --out analysis_search
```

По умолчанию используются пять seed: **0, 1, 2, 3, 4**. `--seeds` принимает
конкретные номера, а не количество: `--seeds 10` означает один запуск с seed 10.
Основные группы — `baseline`, `learning_rate`, `n_steps`, `gae_lambda`, `ent_coef`:
110 запусков A2C при пяти seed. Полный план расширен до **16 серий, 89 позиций
конфигураций и 445 запусков**: 13 обычных серий и три двумерные сетки.
Команды `--suite ofat`, `--suite grids`, `--suite all` выбирают соответствующую часть.
Без этих флагов по-прежнему выполняются только пять основных серий.
Полный список, условия сеток и порядок работы описаны в `docs/EXPERIMENTS.md`.

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --suite all --list --summary
.venv/Scripts/python.exe -m a2c_research.sweep --suite ofat --workers 2
.venv/Scripts/python.exe -m a2c_research.sweep --suite grids --workers 2
```

В обычной серии меняется один фактор. Исключение `n_envs` задаёт связанное изменение
`n_steps`, удерживая размер rollout постоянным: 64 для A2C, 2048 для PPO. Это разные
контрольные rollout, поэтому межалгоритмическое ранжирование чувствительности этой
серии требует осторожности. `n_envs` — число векторизованных сред внутри одного
процесса; `--workers` — число независимых обучений в отдельных процессах.

Полный план выводится перед запуском и сохраняется как `plan_<hash>.json`.
`--list` только печатает план, без обучения и записи файлов. Завершённые запуски
проверяются по конфигурации, версиям, хешу кода обучения и артефактов и переиспользуются.
Общий хеш всех исходников также сохраняется как происхождение результата, но правка
графиков и анализа не инвалидирует модель. Повторяющиеся контроли в разных сериях
обучаются под собственными метками; `unique_training_conditions` в плане показывает
число различных условий с учётом seed. Эти повторы нельзя считать дополнительными
независимыми наблюдениями при объединении серий.
Незавершённый запуск начинается заново, не продолжается с сохранённого оптимизатора.
Ошибки сохраняются в `failure.json` и `failures_<plan>.json`; серия завершается с
ненулевым кодом, если были ошибки. Не удаляйте неудачные seed из исследования:
разберитесь с технической причиной или явно отразите неудачу в статье.

`--workers` задаёт число независимых запусков в процессах. Начните с 1–2 и
определите приемлемое значение по пилоту; это не число сред внутри A2C. Результаты
разных фаз сохраняйте в разных каталогах. Для намеренной перезаписи есть `--force`.
При аварийном завершении процесса может остаться `.running`: убедитесь, что запуск
не активен, и удалите только этот файл перед повтором. Одновременно писать один
и тот же запуск запрещено.

### 3. Проверка выбранных настроек на новых seed

Выберите настройки по исследовательской серии, **до просмотра новых seed**.
Скопируйте `config.json` выбранного запуска в `configs/selected_a2c.json` и
зафиксируйте решение в истории проекта. Этот файл не создаётся автоматически:
выбор нельзя подменять поиском лучшего результата по проверочным seed.

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --config configs/selected_a2c.json --phase confirmatory --out results_confirmatory --list
.venv/Scripts/python.exe -m a2c_research.sweep --config configs/selected_a2c.json --phase confirmatory --out results_confirmatory --workers 2
```

По умолчанию это **20 seed: 1000–1019**. Можно задать другой заранее объявленный
набор `--seeds`. В подтверждающей фазе seed < 1000 запрещены; в поисковой/пилотной
seed >= 1000 запрещены. Проверочные seed могут проверять и замороженную серию
настроек: повторите команду для каждого заранее выбранного конфига. Для вывода о
чувствительности на новых seed проверять нужно диапазон, а не только лучший вариант.
20 повторений — рабочий план, не гарантия статистической мощности.

Одиночный запуск:

```powershell
.venv/Scripts/python.exe -m a2c_research.train --config configs/baseline.json --out results_manual
.venv/Scripts/python.exe -m a2c_research.train --set learning_rate=0.001 --seed 1 --out results_manual_lr
```

### 4. Сравнение с PPO

Для повторения PPO в тех же условиях:

```powershell
.venv/Scripts/python.exe -m a2c_research.sweep --algo ppo --groups baseline --seeds 0 1 2 3 4 --out results_search
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search --out analysis_search
```

Для загрузки полученных ранее результатов коллеги:

```powershell
.venv/Scripts/python.exe -m a2c_research.analyze --results results_search .refs/RL_and_PPO/results --out analysis_combined
```

Нужны каталоги с `config.json`, `eval.csv`, `summary.json` в структуре
`<algo>/<group>/<name>/seed_<seed>/`. Внешние каталоги читаются без изменения.
Идентичные копии запусков не увеличивают число наблюдений. Конфликтующие копии
исключаются обе. Неполные кривые без наблюдений на 0 и заданном бюджете исключаются:
анализ не достраивает отсутствующие точки.

Старые результаты получают метку `reference-unversioned` и используются только
описательно. Прямые разности A2C–PPO рассчитываются для нового протокола при
совпадении общих контролируемых условий, бюджета, сетки оценки, фазы, версий и
идентификатора кода обучения. Архитектура/активация/число сред могут меняться внутри
соответствующих явно объявленных серий. Остальные общие настройки остаются фиксированы.
Все расхождения видны в `analysis.json` и `audit.csv`. Это намеренно
консервативная проверка: наличие одинаковых CSV-колонок не означает одинаковые условия.
Для строгого сравнения со старым PPO потребуется повторить нужные серии по новому
протоколу. Присваивать старым результатам новую метку протокола вручную нельзя.

У алгоритмов одинаковый диапазон learning rate, `gamma`, `gae_lambda`, `ent_coef`.
Диапазоны `n_steps` различаются: A2C — 5, 16, 64, 256; PPO — 64, 256, 1024, 2048.
Поэтому величины чувствительности по `n_steps` напрямую ранжировать нельзя.
`clip_range`, `n_epochs` исследуются только у PPO, `use_rms_prop` — только у A2C.

## Метрики и интерпретация

- **AUC CartPole:** интеграл трапеций по фактическим шагам, разделённый на `500 × бюджет`.
  В отличие от референса это не просто среднее контрольных значений.
- **Итог:** независимая финальная sampled-оценка. Среднее последних пяти точек
  кривой сохраняется отдельно как `last_window_mean`.
- **Межзапусковая стабильность:** стандартное отклонение AUC/итоговой оценки,
  распределения по seed и доля запусков, достигших устойчивого порога.
- **Стабильность внутри запуска:** максимальная просадка от предыдущего пика,
  просадка и доля оценок ниже порога после подтверждения решения. Последние две
  метрики условны по успеху; в таблице явно дано число наблюдений для каждой метрики.
- **Достижение порога:** начало и подтверждение серии двух успешных оценок.
  Не решившие задачу запуски цензурированы на бюджете. Для общего ограниченного
  показателя `restricted_confirmation_steps` им присваивается бюджет. Это не
  прогноз времени будущей сходимости. По одному последнему успеху нельзя судить
  о долгосрочной стабильности: после него может не быть периода наблюдения.
- **Сохранение результата:** `ever_reached` (старое имя `solved`) означает только
  достижение критерия; `retained_at_end` требует последних двух контрольных оценок
  не ниже порога; `collapsed_after_success` отмечает наблюдаемую потерю порога после
  подтверждения; `final_above_threshold` относится к независимой финальной оценке.
  Без наблюдений после подтверждения потеря качества не оценивается: значение пустое.
- **Чувствительность:** разность максимальной и минимальной средней AUC в
  заявленном диапазоне параметра. Рассчитывается только при одинаковых наборах
  seed для всех значений. Интервалы совместно пересэмплируют seed по значениям.
  Оценка зависит от ширины диапазона и плотности сетки; интервалы исследовательские.

Bootstrap выполняется по **независимым обученным моделям**, не по эпизодам и
контрольным точкам. Используются 2000 повторений, seed анализа 2026 и 95%-интервалы.
При одном запуске интервал и выборочное стандартное отклонение отсутствуют.
Для доли успехов используется интервал Уилсона: даже 100% успехов в малой выборке
не означает достоверную вероятность успеха 1. Полосы кривых — поточечные интервалы,
не одновременные. Интервалы разностей не скорректированы за множественные сравнения;
автоматического объявления «победителя» и p-value нет.

Фиксированные оценочные эпизоды улучшают сопоставимость, но ограничивают область
обобщения. Выводы относятся к соответствующей исследованной среде, выбранным диапазонам и указанным
реализациям. Нельзя делать из них вывод о превосходстве A2C/PPO во всех средах.

## Сохраняемые результаты

Один запуск: `config.json` (включая фактические параметры, оптимизатор, версии,
хеш исходников), `eval.csv`, `evaluation_episodes.csv`, `final_episodes.csv`,
`model.zip`, `summary.json`. Последний файл служит признаком завершения и содержит
SHA-256 артефактов. Контрольная точка и итог совместимы с основными именами полей
в референсе; новый анализатор следует использовать для единых научных метрик.

Анализ: `runs.csv`, `summary.csv`, `sensitivity.csv`, `comparison.csv`, `audit.csv`,
`analysis.json`, `report.md`, графики PNG и векторные PDF. Пустой `comparison.csv`
означает, что подходящей пары условий нет. Слои с разными условиями не смешиваются.
Перед использованием в статье проверьте аудит, ошибки и полноту сохранённых планов:
статистика завершённых запусков сама по себе не устраняет смещение из-за пропусков.

Дополнительно сохраняются `grid_cells.csv` (включая отсутствующие ячейки) и
`interactions.csv` с контрастами AUC «разность разностей» относительно первых уровней
двух осей. Четыре ячейки контраста должны иметь одинаковый набор seed. Это
исследовательские интервалы без поправки на множественные сравнения.
В `sensitivity_comparison.csv` отдельно проверяется сопоставимость диапазонов
и связанных контролей A2C/PPO; несопоставимые пары на графике отмечены звёздочкой.

Для каждой серии доступны подписанные траектории seed и диагностика; для сеток —
тепловые карты и линии взаимодействий; для общих условий — сравнения A2C/PPO,
общие обзоры параметров и чувствительности. Список дополнительных рисунков записан
в `analysis.json`. Непараллельные линии сами по себе не доказывают взаимодействие.

Полученный ранее пилот остаётся совместимым через проверенное соответствие хеша
снимка Git `b9e1f85` новому идентификатору обучения в `compatibility.json`.
Это явная таблица аудита для конкретного снимка, а не разрешение смешивать любые
старые результаты. Неизвестные старые хеши сохраняются отдельно.

```powershell
.venv/Scripts/python.exe -m a2c_research.analyze --results results_pilot --out analysis_pilot_extended
```


Тесты проверяют формулы AUC, просадки, цензурирование, изоляцию RNG, повторяемость
обучения, отсутствие влияния частоты оценки на веса, оценку после финального
обновления, точный бюджет A2C/PPO, защиту от повреждённых результатов, импорт
референса, разделение несовместимых условий и формирование графиков.

Основная логика — `src/a2c_research/`, тесты — `tests/`, объявленные конфигурации —
`configs/`. Окружение, референс и экспериментальные артефакты исключены из Git.
Зависимости меняются через локальный pip с одновременным обновлением
`pyproject.toml` и `requirements-frozen.txt`.
